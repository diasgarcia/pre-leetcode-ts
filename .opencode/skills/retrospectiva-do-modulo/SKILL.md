# Retrospectiva do Módulo

Consolidar o que foi aprendido em um módulo e tornar visíveis as lacunas antes de avançar, usando somente evidências do repositório.

## Preparação

1. Ler integralmente `AGENTS.md`, `PROGRESSO.md` e a teoria do módulo solicitado.
2. Se nenhum módulo for informado, selecionar o módulo concluído mais recente.
3. Ler o histórico correspondente em `PROGRESSO.md` e os exercícios concluídos do módulo.
4. Usar `git log` apenas quando necessário para esclarecer a evolução; não executar operações Git mutáveis.
5. Não editar arquivos, atualizar progresso, criar exercícios ou iniciar o módulo seguinte.

## Critério de disponibilidade

Produzir a retrospectiva completa somente para módulo marcado como concluído. Se o módulo ainda estiver em andamento, informar que a retrospectiva final não está disponível e apontar o próximo passo registrado. Produzir uma retrospectiva parcial apenas quando o aluno pedir explicitamente, identificando-a como parcial.

## Análise

Basear cada conclusão em evidências observáveis:

- conceitos cobertos pela teoria e pelos exercícios concluídos;
- padrões de solução efetivamente praticados;
- complexidades registradas no histórico ou verificáveis no código;
- casos extremos tratados;
- sinais concretos de domínio e pontos que merecem revisão.

Não inventar notas, datas, dificuldades, tentativas ou nível de domínio. Distinguir claramente fato observado de recomendação pedagógica.

## Formato da resposta

Apresentar:

1. módulo e situação considerada;
2. aprendizados consolidados, com evidências curtas;
3. padrões de complexidade praticados;
4. lacunas ou riscos reais, se houver;
5. prontidão para o próximo passo;
6. duas ou três perguntas de autoavaliação, sem fornecer as respostas.

Responder em português brasileiro, de forma direta. Não resolver exercícios pendentes nem antecipar a teoria de módulos futuros.
